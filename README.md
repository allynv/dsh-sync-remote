# dsh-sync-remote

**把你的 DSH Web GUI 安全地发布到公网**——用一条 SSH 反向隧道，加一道 Passkey（指纹 / 面容 / Windows Hello / 安全密钥）的门。

想在外面用手机继续一个会话，但又不想把 DSH 暴露在公网上？这个插件解决的问题是：

- 本机的 DSH **只监听回环**，公网上没有任何端口对外开放；
- VPS 上**不装任何常驻服务**，只用自带的 `sshd` 和 Nginx；
- 公网入口前面有一道 **Passkey 门**：没有注册过的设备，连 DSH 的登录页都看不到；
- 会话用 **HttpOnly + Secure + SameSite=Strict** 的签名 Cookie，30 天免登录。

数据怎么走：

```
手机/外部浏览器
      │  https://dsh.example.com
      ▼
   VPS: Nginx（TLS）──► 127.0.0.1:3090 ──► sshd 反向转发
                                                │
   你的电脑                                     ▼
   DSH Web GUI ◄── 127.0.0.1:3080 ◄── Passkey 网关 ◄── 127.0.0.1:3090
       （只监听回环）                  （本插件）
```

网关挡在 DSH 前面：**未通过 Passkey 的请求永远不会到达 DSH**。DSH 自己的启动令牌与 Cookie 依然生效，Passkey 是额外一道门，不是替代它。

---

## 需要准备什么

| 你需要 | 说明 |
| :--- | :--- |
| 一台有公网 IP 的 VPS | 装好 Nginx 与证书（任意方式，Let's Encrypt 即可）；SSH 能登录 |
| 一个域名 | 解析到这台 VPS，例如 `dsh.example.com` |
| DSH 本体 | 本机能跑 `dsh web`（默认 `http://127.0.0.1:3080`） |
| Node.js 26+ | 插件跑在 DSH 进程里，用它执行 TypeScript |
| 一把 SSH 私钥 | 用来连 VPS。**推荐专门生成一把**，见下文「安全建议」 |

## 安装

```powershell
# 1) 取源码
git clone https://github.com/allynv/dsh-sync-remote.git
cd dsh-sync-remote

# 2) 装依赖
pnpm install          # 或 npm install

# 3) 构建浏览器半边（设置页与登录页）
npm run build
```

**4) 装进 DSH 的 web profile**：在 DSH 里让 agent 调用 `plugin_manager install_bundle`，`target` 传本目录的绝对路径。

装好后插件是**空闲**的（还没填公网地址），本机 `http://127.0.0.1:3080` 照常可用。接着按下面两步把它打开。

## 第一步：填配置（在设置页里填，不用改文件）

打开 **设置 → 远程访问**，填入：

| 字段 | 填什么 |
| :--- | :--- |
| **公网地址** | 浏览器访问的地址，如 `https://dsh.example.com`（只填 origin，不带路径） |
| **服务端端口** | VPS 上监听/反代的端口，如 `3090`。**必须与 Nginx 的 `proxy_pass` 一致** |
| **客户端端口** | 本机 `dsh web` 的端口，如 `3080` |
| **会话有效期** | 登录保持多少小时，如 `720`（30 天） |
| **VPS 地址 / 端口 / SSH 用户** | 例如 `203.0.113.10` / `22` / `root`。**端口是 VPS 的 SSH 端口，不是 3090** |
| **私钥路径** | 私钥的绝对路径，如 `C:\Users\me\.ssh\dsh_tunnel_ed25519` |
| **私钥口令** | 仅当私钥有口令时填 |

**保存前必须先「测试连接」**：插件拿你填的这组值把**整条发布链路**走一遍，**全过了才允许写入**：

1. 地址语法（离线，不联网）；
2. 本机 **`客户端端口`** 上真的有 DSH 在应答；
3. 私钥能读、能解析（含口令对不对）；
4. SSH 连上并**认证成功**；
5. VPS 上能绑住 **`服务端端口`**（证明端口没被占、sshd 允许转发）；
6. **公网往返**：从本机 `GET https://<公网地址>/…` 带一个只属于本次测试的随机串，请求必须**回到本插件**——这一步才证明 Nginx 的 `proxy_pass` 端口就是 `服务端端口`、域名真的指向这台 VPS。

测试只做这些，不改任何运行状态：第 5 步绑的端口立刻释放，测试结束时 VPS 与本机都不留监听。

**全新安装也一样**：填完所有必填项直接点「保存并应用」即可——此时还没有任何已保存的配置，测试会**直接拿表单里的值**去验证（包括把指纹写进状态文件），通过才写入。半填的表单不会被判为"故障"，而是明确点名还缺哪一项。

测试通过后这组值会得到一个"配置指纹"记在状态文件里；将来手工改了配置文件、指纹对不上，插件就**不启动远程服务**（不拨号、不绑本机端口），设置页提示你先测试。**指纹覆盖上面 6 步验证过的每一项**，包括 `服务端端口`、`客户端端口`、`公网地址`。

> **改「服务端端口」时，必须先改 Nginx 的 `proxy_pass`，再点测试。** 否则第 6 步到达的是旧端口上的旧隧道，测试会失败——这是刻意的：端口不一致的部署本来就不该被保存。

保存即生效（不需要重启 `dsh`）。每个字段旁边会标出**当前值来自哪一层**（来自插件配置 / 默认值 / 未设置），"固定值"（监听地址、状态文件、RP ID 等）是只读的，不用管。

> **有输入框的字段都是必填的**，代码里没有隐藏默认值——猜错的端口会让"隧道看着正常但公网 502"。填错时页面顶部会用红色横幅点名是哪个字段，没测试通过的配置一个字也不会写进去。

## 第二步：用正确的参数启动 DSH

```powershell
dsh --profile web --public-url https://dsh.example.com/ --trusted-host dsh.example.com
```

这两个参数**必须加**，它们属于 `dsh web` 进程，插件无法代你设置：

- `--trusted-host` 让 DSH 接受公网域名。**少了它，插件什么也不开——公网入口根本不存在**（不是"能登录但界面空白"）：VPS 上不会有 3090 的监听，**本机的网关 3090 也不会监听**，谁也没有机会连进来。插件会在启动日志里直接告诉你加这条，设置页也会显示红色提示。
- `--public-url` 让 DSH 用公网地址生成一次性登录链接。

换句话说：**没有 `--trusted-host`，就没有对外暴露。** 这是刻意的保护，不是故障。改完参数重启 DSH 即可，无需其他操作。

## VPS 侧配置（一次性）

**sshd**：保持默认的 `GatewayPorts no`，不需要开放 3090 端口，也不需要额外开关。

**Nginx**：把域名反代到 `127.0.0.1:3090`。

```nginx
# http{} 里加一行（WebSocket 需要）
map $http_upgrade $connection_upgrade { default upgrade; '' close; }

server {
    server_name dsh.example.com;

    location / {
        proxy_pass http://127.0.0.1:3090;
        proxy_set_header Host $host;          # 必须保留：DSH 按它判定信任
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_buffering off;                  # SSE 需要
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
        proxy_cookie_flags ~ secure httponly;
    }
}
```

证书按你平时的做法签发即可。确认监听只绑回环：

```sh
sudo ss -ltnp | grep 3090     # 期望 127.0.0.1:3090；若是 0.0.0.0 说明 GatewayPorts 被打开了
```

### 一台 VPS 上跑多个部署（很常见的坑）

每个部署要**自己一段 `server` 块**，而且三样东西必须一一对应：

| 项 | 必须对应 |
| :--- | :--- |
| `server_name` | 该部署的域名（**不能**复制过来忘了改） |
| `proxy_pass` 端口 | 该部署设置页里的「服务端端口」 |
| `--trusted-host`（那台机器上启动 DSH 时） | 同一个域名 |

```nginx
# 部署 A（老机器）
server { listen 443 ssl; server_name dsh.example.com;  location / { proxy_pass http://127.0.0.1:3090; ... } }
# 部署 B（新机器）——server_name 必须改，端口必须是 B 自己的
server { listen 443 ssl; server_name xyb.example.com;  location / { proxy_pass http://127.0.0.1:3091; ... } }
```

**两个自查命令**（复制粘贴错误就靠它们暴露）：

```sh
sudo nginx -t | grep -i conflict
# 出现 conflicting server name "xxx" ... ignored ⇒ 有两段块用了同一个 server_name，
# 后一段整个被 Nginx 忽略（它的 proxy_pass 端口等于从未生效），而未配置的域名会落到
# 默认站点（同机器上的别的服务）上去。

curl -sS -o /dev/null -w '%{http_code}\n' -H 'Host: xyb.example.com' http://127.0.0.1/
```

判断标准很简单：**新的域名应当返回 502**（Nginx 指向了它该指的那个端口，而那个端口上此刻还没有隧道）；如果返回的是 403/404/200，说明它被交给了**别的站点**——回到上面那张表逐项对。把这些都对好之后，设置页的「测试连接」就是最终的端到端判据。

## 开始使用

> **设置页只能在运行 DSH 的那台机器上编辑**：用 `http://127.0.0.1:<本机 DSH 端口>`（默认 3080）打开，输入框才是可写的；用公网域名打开时页面是只读的（这是插件自己强制的规则）。远程运维时可以用 `ssh -L 3080:127.0.0.1:3080 user@你的机器` 把回环页面转发到自己机器上，那也算回环。实在不方便就手改 `~/.dsh/profiles/web/cordis.patch.yml`。

1. **注册第一台设备**：打开设置页 → 「生成注册二维码」→ 用手机扫码（或复制链接打开）。
   首次安装时，若一把 Passkey 都还没有，插件启动时**已经自动生成了一条链接**，打印在运行 `dsh` 的终端里，同时也写到 `~/.dsh/dsh-sync-remote/enroll-url.txt`。

2. **完成注册**：手机弹出指纹/面容/PIN → 确认 → **自动进入 DSH**，无需再输任何东西。

3. **之后随时访问** `https://dsh.example.com`：会先看到 Passkey 登录页，验证后进入 GUI（30 天内免验证）。

4. **加设备**：设置页里再点一次「生成注册二维码」，用新设备扫。**每个二维码只能用一次**，10 分钟内有效，用完或超时即失效。

5. **删设备**：设置页的「已注册设备」列表里删除。最后一把 Passkey 不可删除（防止把自己锁在门外）。

## 安全建议

- **别把私钥的权限放大。** 默认情况下隧道私钥能在 VPS 上开 shell。建议在 VPS 的 `~/.ssh/authorized_keys` 里把它限制成只能做这一个转发：
  ```
  restrict,port-forwarding,permitlisten="127.0.0.1:3090" ssh-ed25519 AAAA…你的公钥… dsh-sync-remote
  ```
  之后这把钥匙**不能登录 shell、不能执行命令、不能开别的端口**。

- **DSH 打印的 `?token=…` 链接本身就是钥匙**，别贴到公开渠道。Passkey 是额外一道门，不是让这条链接失效。

- **状态文件是凭据**，按私钥对待：`~/.dsh/dsh-sync-remote/state.json` 里是签名密钥和已注册的 Passkey。备份它等于备份身份；丢了就要重新注册所有设备。

- 注册链接是**一次性**的，只存在内存里：重启即失效，磁盘上没有任何长期注册凭据。

- 登录/注册接口按来源地址限流（5 分钟 30 次），超限是**延迟响应**而不是锁定——你自己不会被锁在门外。

## 遇到问题

| 现象 | 原因与处理 |
| :--- | :--- |
| 设置页里隧道显示 `blocked`（红点）、网关显示「未启动」、公网打不开 | 启动 DSH 时少了 `--trusted-host`。插件**什么都不开**：VPS 上无监听（在 VPS 上 `ss -ltnp \| grep 3090` 确认无输出），本机网关端口也不绑定。用上面的命令重启 DSH。设置页照常可用——它由 DSH 自己的 3080 提供，不依赖网关。 |
| 公网 **502**，但插件日志显示隧道正常 | `服务端端口` 与 Nginx 的 `proxy_pass` 不一致。改成同一个值（先改 Nginx，再点「测试连接」，通过后保存）。 |
| 测试连接报「公网域名没有回到本机」 | 第 6 步失败：Nginx 到了 VPS，但那个端口上没有隧道——几乎总是 `proxy_pass` 端口 ≠ `服务端端口`；也可能是 Nginx 指到了别的服务，或 CDN 缓存了旧内容。页面会说明是哪一种。 |
| 测试连接报「VPS 拒绝监听服务端端口」 | 第 5 步失败：端口被占（常见是上一次会话残留的 sshd）或 sshd 禁止转发。在 VPS 上 `sudo ss -ltnp \| grep <端口>` 查明；开了「释放 VPS 端口」可以一键处理。「立即重试」也可以。 |
| 测试连接报「本机客户端端口上没有 DSH」 | 第 2 步失败：`客户端端口` 写错了，网关会把它反代进一个空洞，访客只会看到 502。填成 `dsh web` 实际监听的端口。 |
| 测试连接报「从这台机器访问不到公网地址」 | 第 6 步失败在 DNS/证书/网络上：确认域名解析到你的 VPS、证书有效，且这台机器能上公网（有些内网 split DNS 解析不到自己的公网域名）。 |
| 隧道显示 `untested（配置未验证）`、网关「未启动」、公网打不开 | 这组配置没有通过测试（多半是手工改过配置文件，或升级后还没测过）。插件**不拨号、不绑端口**。点「测试连接」，成功后再保存即可。 |
| 改了隧道字段点「保存并应用」没反应 | 保存前会先跑一次连接测试，**测试不通过就不写入**。页面会显示原因：先按原因把值改对，再保存。 |
| 测试连接报 `key` | 私钥读不到、格式不支持（只支持 OpenSSH、PKCS#1、SEC1、PuTTY PPK，**openssl 默认的 PKCS#8 会被拒绝**）、私钥有口令但没填口令，或口令不对。页面会点名是哪一个。 |
| 测试连接报 `auth` | 服务端拒绝了这次身份：`SSH 用户` 写错、公钥没在目标用户的 `authorized_keys` 里，或被 sshd 策略挡住。用同样的命令在 VPS 上复现最快：`ssh -i <私钥> -p <端口> <用户>@<地址>`。 |
| 测试连接报 `host-key` | 对方出示的主机密钥与已固定的不一致——地址写到了别人机器，或 VPS 重装过。确认是自己的 VPS 后点「重新信任」；否则先核对「VPS 地址」。 |
| 状态是 `reconnecting (dns/unreachable/handshake-timeout)` | 这组配置**已经测试通过**，所以更可能是 VPS 没起、被防火墙/安全组挡，或本机网络问题。这类**会**自动重连（退避最长 5 分钟），期间公网返回 502。 |
| 日志报 `VPS 拒绝监听 127.0.0.1:3090` | 上一次会话没释放端口。按提示在 VPS 上 `sudo ss -ltnp \| grep 3090` 并结束那个 sshd；想让它自动处理，打开设置页的「**释放 VPS 端口**」（默认关；开启后插件会在同一个 SSH 用户下执行 `ss -ltnp`，**确认占用者是 sshd 后**才 `kill <pid>`）。根治办法见 `CONTRIBUTING.md` 的 `ClientAliveInterval` 说明。 |
| 手机扫码后提示链接无效 | 每个二维码只能用一次、10 分钟有效。回设置页重新生成一个。 |
| 换了 VPS 或重装了系统 | 设置页里「已固定主机密钥」旁边点「重新信任」。 |
| 隧道断了会自动恢复吗 | 会。日志出现 `tunnel lost … reconnecting in … ms` 后会自动重连（指数退避，最多 1 分钟；连续没连上会放慢到 5 分钟），期间公网返回 502。**只有测试验证过的配置才会重连**；没验证过的配置根本不启动。 |
| 想看更详细的运行状态 | 设置页顶部有网关/隧道/围栏状态；插件只把**需要你处理的事**打到控制台。 |

## 已知限制

- 一个插件行只支持**一台 VPS、一条端口映射**；多目标就再挂一个插件行（id 不同）。
- 升级到带「测试连接」的版本后，已有部署第一次启动会显示 `untested`（老配置没有验证记录），点一次「测试连接」即恢复。这是刻意 fail closed：宁可停一次，也不放行一组没人验证过的值。
- 测试里的**公网往返**要求运行 DSH 的这台机器能访问自己的公网地址（走 DNS + TLS，和手机走的是同一条路）。内网 split DNS 或本机出网受限时会失败；这种情况下没有"跳过公网校验"的开关——跳过就等于放行一组端口没验证过的配置。
- 公网往返只在「测试连接」和「保存前」跑，**运行期不做巡检**：隧道起来之后 Nginx 被改坏，插件不会主动发现（设置页仍显示隧道 `listening`，公网 502）。
- 不支持把 DSH 挂在子路径下（如 `https://example.com/dsh/`），本插件按 origin 根路径设计。
- 依赖 `@simplewebauthn/server` 会在启动时打印两条 Node 实验性特性警告，**与功能无关**，可以忽略。
